# Проверки

Сначала выполните `setup.cmd`. Все команды ниже запускаются из корня проекта в CMD.

## Без оборудования

```cmd
test\.venv\Scripts\python.exe -m unittest discover -s tests -p test_worker.py -v
dotnet run --project tests\BindingTests -c Release
dotnet run --project tests\MixerTests -c Release
dotnet run --project tests\StorageTests -c Release
dotnet run --project tests\DesktopTests -c Release
test\.venv\Scripts\python.exe tests\api_integration.py
```

Проверяются жизненный цикл BLE-сессий через подставной контроллер, атомарное
сохранение ключей, восстановление путей, миграция в AppData, расчёт микшера,
объединение очереди, автоподключение, HTTP-аутентификация и управление микшером.
HTTP-проверка запускает отдельный экземпляр приложения с временными данными,
фиктивными адресами и выключенным автоподключением. Реальные ключи не используются.

## Проверка окна

Используйте отдельную папку данных, чтобы не задействовать настройки реальных ламп:

```cmd
build\Godox.Desktop.exe --root "%CD%" --data-dir "%CD%\artifacts\ui-preview" --smoke
```

Окно открывается, сохраняет снимки в `artifacts` внутри указанной папки данных
и закрывается. Пустой первый запуск также поддерживается.
`--mixer-smoke` предназначен для вручную подготовленного демонстрационного набора
из двух отключённых профилей с выключенным автоподключением; он проверяет события
ползунков, сохранение пропорций, перестановку колонок и блокировку кнопки подключения.

```cmd
test\.venv\Scripts\python.exe tests\desktop_integration.py
test\.venv\Scripts\python.exe tests\startup_integration.py
```

Этот сценарий сам создаёт отключённые демонстрационные профили и проверяет
закрытие в трей, работу HTTP и хоткеев со скрытым окном, восстановление при повторном
запуске и полное завершение через «Выход». Снимок вкладки настроек сохраняется рядом
с остальными. Для автономной сборки добавьте `--exe dist\Godox-win-x64\Godox.Desktop.exe`.
Проверка регистрации автозапуска в `DesktopTests` использует отдельный временный
раздел реестра; настоящий автозапуск пользователя не меняется.

`startup_integration.py` запускает отдельные экземпляры с разными сочетаниями
обычного/автоматического запуска, старта в трее, закрытия в трей и HTTP API.
Проверяет отсутствие даже кратковременного показа окна при скрытом старте,
а также реальное наличие или отсутствие слушающего локального сервера.

## На настоящих светильниках

Закройте Godox Desktop, тестовый контроллер и Godox Light на телефоне.
Нужны сохранённые профили и рабочие привязки в AppData.

```cmd
test\.venv\Scripts\python.exe tests\mixer_hardware.py --hardware
```

Проверка использует отдельные настройки, но исходные файлы ключей и счётчиков.
Она ненадолго выставляет небольшую яркость, проверяет общий множитель,
приглушение и задержку отправки, затем восстанавливает исходные значения.
Если проверка восстановления не прошла, сверьте настройки на экранах светильников.

`--lifecycle-smoke` у приложения дополнительно подключает сохранённые приборы,
применяет их микшер и проверяет нормальное закрытие с активными соединениями.
Аппаратные проверки не должны запускаться автоматически при обычном тестировании.
