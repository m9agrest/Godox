# Godox Desktop

Приложение для Windows: управление светильниками Godox по Bluetooth, микшер яркости,
глобальные горячие клавиши и локальный HTTP API.

**Автор:** [m9agrest](https://github.com/m9agrest) · **Лицензия:** [MIT](LICENSE)

Неофициальный проект. Проверено на **SL60IIBi** и **P260C Pro** в режиме CCT:
яркость 0–100%, температура 2800–6500 K с шагом 100 K. Другие модели пока не поддерживаются.

## Возможности

- Яркость и температура применяются при движении ползунков.
- Общий микшер умножает уровни ламп, сохраняя их пропорции:
  `100% / 50%` при общем уровне `50%` дают `50% / 25%` на приборах.
- В скобках показана расчётная яркость с учётом общего уровня и приглушения.
- Общее и индивидуальное приглушение сохраняют положения ползунков.
- Подключение и отключение из каждой колонки либо сразу для всех ламп.
- Автоподключение и восстановление связи: общий переключатель и отдельный для каждой лампы.
- Перестановка колонок стрелками ← / → с сохранением порядка.
- Настраиваемые глобальные хоткеи и HTTP API для внешних программ.
- Автозапуск вместе с Windows и закрытие окна в трей с сохранением работы приложения.
- Неактивная кнопка «Подключается…» во время ручного и автоматического подключения.

## Установщик и автономная версия

`build.bat` создаёт выпуск для Windows x64, в который уже включены **.NET 10,
Python 3.12 и Bluetooth-библиотеки**. На компьютере пользователя устанавливать
.NET, Python или Git отдельно не нужно; интернет для установки также не нужен.
Нужны Windows 10/11 и работающий BLE-адаптер.

Результаты сборки:

- `dist/installer/Godox-Desktop-0.2.1-Setup-x64.exe` — установщик Inno Setup.
- `dist/Godox-Desktop-0.2.1-win-x64.zip` — автономная папка без установки.
- `dist/Godox-win-x64` — содержимое автономной сборки.

Установщик работает для текущего пользователя без прав администратора:
программа — `%LOCALAPPDATA%\Programs\Godox Desktop`, настройки и привязки —
`%LOCALAPPDATA%\Godox`. Удаление программы сохраняет пользовательские данные.
Для ZIP-версии распакуйте **всю папку** и запустите `Godox.Desktop.exe`.

Для сборки установщика на компьютере разработчика нужны .NET 10 SDK,
Python 3.12 x64, Git и Inno Setup 6. Интернет нужен только во время сборки.

```cmd
build.bat
```

Только автономная папка и ZIP, без Inno Setup: `build.bat -SkipInstaller`.
Скрипт проверяет SHA-256 дистрибутива Python и включает закреплённые зависимости
из `packaging/requirements-win-x64.txt`. Подробности — [docs/PACKAGING.md](docs/PACKAGING.md).

## Автозапуск и трей

Во вкладке **«Настройки»** доступны независимые переключатели:

- **«Запускать вместе с Windows»** — запуск при входе в учётную запись, без прав
  администратора. Настройка хранится в пользовательском разделе автозапуска Windows.
- **«При закрытии оставлять в трее»** — крестик скрывает окно, сохраняя Bluetooth,
  горячие клавиши и запущенный HTTP API.
- **«При автозапуске сразу запускать в трее»** — при входе в Windows окно вообще
  не показывается. Обычный запуск через ярлык открывает окно независимо от этой настройки.
  Работает независимо от поведения крестика; по умолчанию выключен.
- **«Запускать локальный сервер при запуске программы»** — включает HTTP API при
  следующем запуске, в том числе автоматическом. Сохраняется сразу. Прежний выбор
  `apiEnabled` сохраняется при обновлении; на новой установке сервер включён.

Нажатие значка Godox или повторный запуск приложения возвращает существующее окно.
Для полного завершения выберите **«Выход»** в меню значка или **«Выйти из приложения»**
в настройках. Настройки Windows-автозапуска и закрытия в трей по умолчанию выключены.
Удаление установленного приложения также удаляет запись его автозапуска.

## Запуск из исходников для разработки

Потребуются Windows 10/11 с BLE-адаптером, **.NET 10 SDK**, **Python 3.12** и **Git**.
Команды `dotnet`, `python` и `git` должны быть доступны в терминале.
Для установки зависимостей нужен доступ к NuGet, PyPI и GitHub.

```cmd
git clone https://github.com/m9agrest/Godox.git
cd Godox
setup.cmd
start.cmd
```

`setup.cmd` создаёт Python-окружение в `test\.venv`, устанавливает закреплённые
зависимости и собирает приложение в `build`. `start.cmd` запускает готовую сборку.

Сборка через `setup.cmd` предназначена для разработки: она зависит от установленных
.NET Desktop / ASP.NET Core Runtime 10 и окружения `test\.venv`.
Для распространения используйте `build.bat`. Сборки, установщики и Python-окружения
в Git не хранятся.

## Первое подключение

Новая установка начинается с пустого списка устройств.

1. Включите питание и Bluetooth на светильнике, закройте Godox Light на телефоне.
2. Нажмите **Найти по Bluetooth** или **Добавить**, выберите модель и MAC своего прибора.
3. Если привязки к этому ПК ещё нет, сбросьте Bluetooth на приборе.
4. Нажмите **Подключить** и подтвердите создание привязки. Ключи сохранятся автоматически.

Сброс Bluetooth заменяет прежнюю привязку к телефону. Для последующих подключений
повторный сброс не нужен. Существующий файл привязки можно выбрать в **Настроить**;
он будет перенесён в папку данных приложения. MAC в файле должен совпадать с прибором.

**Отключить** освобождает Bluetooth и сохраняет текущий свет.
**Погасить** отправляет 0%, сохраняя соединение и уровень ползунка.
Для чтения фактического состояния используйте **Ещё… → Прочитать состояние**.
При закрытии приложения соединения освобождаются, а свет остаётся как есть.

## Автоподключение и горячие клавиши

Автоподключение работает при включённом общем флажке и флажке у конкретной лампы,
если файл привязки существует. Общий флажок новой установки выключен.
Проверка связи выполняется каждые 3 секунды, повтор после ошибки — через 30 секунд.
Автоподключение не сбрасывает Bluetooth и не создаёт новые ключи.

Ручное отключение ставит автоподключение лампы на паузу до перезапуска,
ручного подключения или повторного включения соответствующего флажка.
При подключении применяется сохранённое состояние микшера.

Хоткей лампы задаётся в **Настроить**, например `Ctrl+Alt+1`; он переключает
её приглушение. Пустое поле отключает хоткей. `Ctrl+Alt+0` приглушает общий микшер.
Хоткеи работают при свёрнутом окне и не подключают отключённые приборы.
Общее включение хоткеев находится на вкладке **Интеграция**.

## Данные приложения

По умолчанию: `%LOCALAPPDATA%\Godox`.

| Путь | Содержимое |
|---|---|
| `settings.json` | Устройства, микшер, порядок, хоткеи, настройки и токен API |
| `bindings\<MAC>_mesh_state.json` | Ключи Bluetooth Mesh и счётчики команд |
| `bindings\binding-backups` | Старые привязки после перепривязки |
| `migration` | Архив настроек после переноса старой версии |
| `logs\errors.log` | Ошибки запуска |

Старые настройки из `data\settings.json` и используемые ими ключи автоматически
переносятся при первом запуске обновлённой версии. Ключи перемещаются целиком:
две рабочие копии привязки могут рассинхронизировать счётчик Mesh-сообщений.
Удаление устройства из списка не удаляет его ключи.

Не публикуйте настройки, токены, привязки и диагностические Bluetooth-дампы.
`.gitignore` исключает локальные данные, сборки и журналы.

## HTTP API

Сервер по умолчанию слушает только `http://127.0.0.1:8765`.
Токен копируется на вкладке **Интеграция** и передаётся в заголовке `X-Godox-Token`.
Порт и включение сервера применяются после перезапуска. CORS не включён.

| Запрос | Действие |
|---|---|
| `GET /health` | Проверка сервера без токена |
| `GET /api/devices` | Список устройств, их ID и последнее известное состояние |
| `GET /api/mixer` | Общие `level` и `muted` |
| `POST /api/mixer` | Общие настройки, например `{"level":50,"muted":false}` |
| `POST /api/devices/{id}/mixer` | Уровень и/или приглушение лампы |
| `POST /api/devices/{id}/set` | `{"brightness":50,"cct":4000}` — оба поля обязательны |
| `POST /api/devices/{id}/connect` | Подключить |
| `POST /api/devices/{id}/disconnect` | Отключить |
| `POST /api/devices/{id}/status` | Прочитать состояние с прибора |
| `POST /api/devices/{id}/toggle` | Переключить приглушение |
| `POST /api/devices/{id}/off` | Приглушить |
| `POST /api/connect-all` | Подключить все сохранённые приборы |
| `POST /api/disconnect-all` | Отключить все |
| `POST /api/scan` | Поиск Godox поблизости |

В `set` поле `brightness` задаёт уровень **до общего множителя**, а индивидуальное
приглушение снимается. `mixer` может сохранять настройки отключённой лампы для
следующего подключения. Ответ устройства содержит `level`, `effectiveBrightness`,
`muted`, `connected`, `autoConnect`, `autoPaused`, `brightness`, `cct`, `warning`.
Ключи Bluetooth через API не выдаются.

Пример для CMD:

```cmd
set "GODOX_TOKEN=YOUR_TOKEN"
curl.exe -H "X-Godox-Token: %GODOX_TOKEN%" http://127.0.0.1:8765/api/devices
curl.exe -X POST -H "X-Godox-Token: %GODOX_TOKEN%" -H "Content-Type: application/json" -d "{\"level\":50}" http://127.0.0.1:8765/api/mixer
```

Запуск без окна: `build\Godox.Desktop.exe --headless --root "%CD%"`.
Глобальные хоткеи в этом режиме не регистрируются.

## Разработка и проверки

Окно, настройки, хоткеи и HTTP-сервер: C# / WPF / .NET 10.
Bluetooth: постоянный Python-процесс `backend/worker.py`, обмен с C# через JSON.
Протокол предоставляет [ha-godox-mesh](https://github.com/binary-person/ha-godox-mesh).
Версии Python-зависимостей закреплены в `test/requirements.txt`.

Проверки без светильников:

```cmd
dotnet build Godox.slnx -c Release
test\.venv\Scripts\python.exe -m unittest discover -s tests -p test_worker.py -v
dotnet run --project tests\BindingTests -c Release
dotnet run --project tests\MixerTests -c Release
dotnet run --project tests\StorageTests -c Release
dotnet run --project tests\DesktopTests -c Release
test\.venv\Scripts\python.exe tests\api_integration.py
test\.venv\Scripts\python.exe tests\desktop_integration.py
test\.venv\Scripts\python.exe tests\startup_integration.py
```

HTTP-проверка использует отдельные временные настройки и требует готовую сборку
в `build` после `setup.cmd`. Аппаратные и визуальные проверки описаны в
[docs/TESTING.md](docs/TESTING.md); диагностические скрипты — в [test/README.md](test/README.md).
Для изоляции данных используйте `--data-dir "ПОЛНЫЙ_ПУТЬ"`. `--root` задаёт папку
программы, backend и Python-окружение. Один экземпляр приложения работает с одной папкой данных.

## Ограничения

- Ползунки объединяют изменения примерно раз в 75 мс, отправляя последнее значение.
  Поиск, подключение и явное чтение состояния временно занимают Bluetooth-канал.
- Успешная быстрая запись подтверждает отправку, а не физическое применение.
  Ответ светильника может запаздывать; перед проверкой состояния нужна короткая пауза.
- После новой привязки P260C Pro иногда возвращает недостоверную температуру.
  Приложение показывает предупреждение; сверяйте первоначальный ответ с экраном прибора.
- RGB, эффекты и другие модели пока не реализованы.
